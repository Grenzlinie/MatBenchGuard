# Repair Categories

## Structure and configuration

Repair parser errors, broken paths, filename mismatches, invalid weights, missing deterministic fields, and output-directory creation. Preserve public interfaces unless correcting a documented inconsistency.

## Instruction and contract

Clarify required inputs, outputs, columns, types, units, reference versions, coordinate systems, sorting, duplicates, missing values, tolerances, and allowed tools. Do not invent scientific parameters.

## Resource and environment

Prefer official accessions, immutable release files, checksums, mirrors, package pins, container digests, and compatible solvers. Never bypass access controls or rehost restricted data without permission.

## Checker coverage and logic

Validate all core scientific artifacts, reject missing or infeasible outputs, avoid hard-coded result-only checks, and give meaningful partial credit where the answer type supports it.

## Leakage and reproducibility

Repair patient, donor, study, sequence-family, scaffold, cohort, or near-duplicate leakage using domain-appropriate group splits. Pin seeds, versions, snapshots, and tolerances.

## Gold and paper consistency

Only repair Gold when its correct source and generation procedure are public and unambiguous. Otherwise mark the task abandoned. Do not replace experimental truth with a convenient computational proxy without changing the declared construct.
