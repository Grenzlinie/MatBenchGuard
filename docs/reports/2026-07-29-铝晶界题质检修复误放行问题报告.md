## 3. 题包实际存在的问题

## 3.1 晶体学定义错误

题面声称：

> Σ3(1-11) 和 Σ9(2-21) 使用 `[001]` tilt axis。

论文实际只说两晶粒的 `[001]` 方向用于定义错配角，没有把 `[001]` 定义为这两个晶界面的共同倾转轴。

对于晶界面法向：

```text
n1 = [1, -1, 1]
n2 = [2, -2, 1]
n1 × n2 = [1, 1, 0]
```

共同面内方向为 `[110]`。`[001]` 与两个面法向的点积均不为零，因此不在任一晶界面内，不能作为这两个面的共同 tilt axis。

历史初审 2.3 只以“LAMMPS + EAM + CSL 属于合理方法”为由给出 PASS，没有进行最基本的晶体学不变量检查。

## 3.2 同一输出存在三套合同

`gb_energy_effect.csv` 至少存在三种互相冲突的定义：

| 来源 | 行数/载荷 | 标签 |
|---|---|---|
| Repair 后 `instruction.md` 复现目标与 Step 8 | 两个晶界、仅 `0.00117`，共 2 行 | ASCII `Sigma` |
| `steps.json` Step 7/8 | 三个载荷 × 两个晶界，共 6 行 | 未锁定 |
| `grading_spec.json` 的描述和 notes | 声称三个载荷并检查单调性 | 未真正实现 |
| `checker.py::score_3` | 字典中每个晶界只保留一个值，载荷列完全不读 | 只接受 ASCII `Sigma` |
| `solution/solve.sh` | 三个载荷 × 两个晶界，共 6 行 | Greek `Σ` |

历史 Repair 选择了“把题面改成 checker 当前接受的两行单载荷”，而不是依据论文、steps 和完整科学目标解决合同。这是典型的 **prompt-to-checker overfit**。

## 3.3 Checker 没有评估题目声称的核心自变量

### 时间坐标未验证

- sliding scorer 选择“离 5 ps 最近的行”，不要求该时间真的接近 5 ps；
- migration scorer 直接读取最后一行，不检查最后时间；
- 因此错误时间轴也能满分。

### 载荷未验证

`score_3` 读取：

```python
data = {
    r["boundary_label"].strip(): float(r["sliding_at_5ps"])
    for r in rows
}
```

`force_per_volume_eV_per_A4` 只在 shape gate 中要求列存在，评分逻辑完全忽略其值。

### 重复键覆盖

同一字典推导式会用最后一条同名记录覆盖之前记录；没有拒绝重复晶界、重复时间或冲突坐标。

### 能量组件分母错误

`score_0` 的最高累计贡献为：

```text
1 + 1 + 1 + 0.5 + 0.5 = 4
```

但最终固定除以 `checks = 5`，所以完全满足所有条件的能量结果最高只能得到 `0.8`。

## 3.4 动态攻击证明 checker 可被绕过

| 探针 | 奖励 | 说明 |
|---|---:|---|
| 有效正例 | 0.94 | 高于 0.6 |
| 错误时间轴/载荷的极小输出 | 0.94 | 与有效正例同分 |
| 重复关键键攻击 | 0.64 | 通过 |
| 四组件明显降质输出 | 0.60706 | 通过 |
| 单独能量组件 | 0.24 | 未单组件绕过 |

题面最后声称：

> Reproducing the full computational pipeline ... is essential; simply reporting plausible numbers ... will not yield results that survive...

动态证据直接否定这一声明：少量命中特征的合成 CSV 即可得到 0.94。

## 3.5 作者自检本身没有执行科学流程

`solution/generate.py` 直接生成解析曲线和论文文字中的数值，`solution/solve.sh` 不运行 LAMMPS。它还输出 Greek `Σ`，与 Repair 后公开要求的 ASCII 标签冲突。

依据 Review/Repair 原则，solution 不能作为 Gold 或科学正确性的证据；但它应作为 packaging smoke test。历史流程既没有用它证明科学，也没有发现它连修复后的公开合同都不满足。

## 6. 根因分析

## 6.1 根因树

```text
误放行
├── Review 漏检
│   ├── 科学审核停留在主题/方法名称
│   ├── 没有晶体学不变量检查
│   ├── 没有逐字段/逐自变量评分追踪
│   └── 通用垃圾输入替代任务特定攻击
├── 决策证据不一致
│   ├── quality_gradient 原始状态 NOT_ASSESSED
│   ├── component_isolation 原始状态 NOT_ASSESSED
│   └── 决策文件仍手工写 PASS
├── Validator 未拦截
│   ├── 只验证 JSON 字段、分数和 verdict 内部一致性
│   └── 不读取 checker_observations.json
├── Repair 范围锚定
│   ├── 只处理初审发现的 F1/F2
│   ├── 没有修复前 fresh-defect pass
│   ├── 没有跨文件 impact matrix
│   └── 合同修复迎合 checker，而非回到论文与科学目标
├── 复审不独立
│   ├── 复用初审 rationale
│   ├── 没有重新构造攻击
│   └── “修复目标已关闭”等同于“全题已通过”
└── 发布态缺少闭环
    ├── 不验证必要 URL
    ├── 不运行作者 smoke test
    └── 不比较 Playground、candidate 与 _publish
```

## 6.2 为什么旧 validator 会接受

旧版 validator 只消费 `agent_final_decision.json`。只要该文件写：

```json
{"quality_gradient": {"status": "PASS"}}
```

并且其他字段、分数和 verdict 算术自洽，就可以验证通过。它不会打开 evidence 文件确认真正的 raw status。

历史记录使用 schema 2.0，仅含四个硬门槛；当前 2.1 已加入 `SCIENTIFIC_REASONING_ABSENT`，但在补丁前仍保留相同的“信任声明状态”问题。

## 6.3 为什么 Repair 放大了错误

Repair 的输入是初审 findings。如果初审只发现格式问题，Repair 会自然地只修格式问题。所谓“同等深度复审”如果仍复用相同探针、相同 rationale 和相同盲点，就只是确认已知 finding 被关闭，而不是重新审核完整题包。

因此必须把：

```text
target closure
```

和：

```text
fresh full-package review
```

定义为两个独立 Gate。

## 7. BioPaperBench 可迁移经验

## 7.1 值得迁移

### 分阶段 Gate

按成本和证据类型拆分：

1. 结构/哈希；
2. 资源/预算；
3. 题面/checker 静态审计；
4. 论文/Gold 精读；
5. 动态 attack matrix；
6. 最终证据一致性。

这种拆分可防止一个笼统的“整体感觉合理”覆盖多个独立判断。

### 显式 attack matrix

BioPaperBench 把全基因组覆盖、随机基线、空输出、score 反转等攻击写成固定测试矩阵。材料侧应采用同样思想，但按输出类型生成：

- 表格：重复主键、冲突坐标、错单位、错时间/载荷、排序置换；
- 曲线：稀疏特征点、错误横轴、局部命中、质量逐级退化；
- 结构：错误晶胞、原子重叠、元素错配、周期边界错误；
- 标量：单位换算、符号、数量级、容差边界；
- 模型：空权重、常数预测、错误数据 split、随机 seed；
- 图像：尺寸/通道/掩膜/对抗元数据。

### Gold 的统计学/物理红旗

生物侧检查等宽、等间距和数量级异常。材料侧可以增加：

- 晶体学面—轴不变量；
- 维度分析与单位一致性；
- 对称性和周期性；
- 守恒量和边界条件；
- 物理范围与单调关系；
- Gold 采样密度与坐标覆盖；
- 重复键和伪造解析曲线特征。

### 资源和预算独立 Gate

资源可达性、身份/version/hash、许可、时间、内存和存储不能混在“题面看起来完整”中判断。

## 7.2 不能直接照搬的部分

将 BioPaperBench 脚本直接运行在本题上，得到：

| Phase | 结果 | 实际问题 |
|---|---|---|
| Phase 0 | PASS | 只能核对文件名集合，未发现两行/六行、axis 或 scorer 语义 |
| Phase 1 | PASS | 没解析嵌套 `resources[].access.url`，实际检查 URL 数为 0 |
| Phase 4 | SKIP | tests 下没有外置 BED/CSV Gold，无法适配 Harbor checker |

因此需要迁移**架构和测试设计原则**，并为材料题包的 schema、checker entrypoint 和输出类型重新实现 adapter，不能把生物脚本当成通用 validator。
