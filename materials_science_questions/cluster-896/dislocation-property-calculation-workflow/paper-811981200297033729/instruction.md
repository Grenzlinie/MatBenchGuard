# Screw Dislocation Core Widths near a Bimaterial Interface

## Problem background
The behavior of a screw dislocation near a bimaterial interface between two crystals with different elastic moduli is not fully captured by continuum elasticity. Atomistic simulations can reveal how the dislocation core structure changes asymmetrically when approaching the interface from the 'soft' (lower modulus) or 'hard' (higher modulus) side. This task quantifies those changes by computing the core half-width (in units of the lattice parameter a0) of an a0[001] screw dislocation at various distances from a (100) interface in a bcc bicrystal. Two different interatomic potentials representing alpha-iron (a pair potential and an N-body potential) are used to test the robustness of the core behavior. The computed core widths for different dislocation positions will be compared under the same simulation conditions.

## Approach
The method uses atomistic simulations of a bicrystal with a (100) interface at x=0 and a lattice parameter a0=0.286 nm. The simulation cell contains 800 atomic rows in a 20a0×20a0 central region. A screw dislocation with Burgers vector a0[001] is introduced using the elastic image construction for a bimaterial, which provides initial displacements. The two interatomic potentials are applied with scaling rules: for the pair potential, interactions in the hard medium are scaled by α=2 and mixed interactions use the arithmetic mean; for the N-body potential, the pair part is scaled by α and the non-pair part by α². Core half-width is determined by computing the distribution of screw relative displacements across the {110} glide plane after conjugate-gradient relaxation under an applied uniform shear strain that stabilizes the dislocation. The half-height width of this distribution yields the core width in a0 units. Configurations are classified by their extent in elementary squares (2C, 4C, 9C, etc.). The homogeneous crystal (no interface) serves as a baseline to measure the intrinsic core width for each potential.

## Reproduction target
The goal is to produce two CSV files: core_widths_pair_potential.csv and core_widths_nbody_potential.csv. Each file must contain the core half-width and configuration type for the dislocation at seven positions relative to the interface: x = -2.5, -1.5, -0.5, 0, 0.5, 1.5, 2.5 a0 (negative means the soft medium). Additionally, the homogeneous reference core width must be included as a row with position 'homogeneous'. The columns are position_a0, core_width_a0 (a positive number), and configuration_type (a string). The data should be generated by running the full simulation protocol described in the workflow steps for each potential, not by copying numbers from any external source.

## Assets

- Johnson pair potential for alpha-iron (Johnson 1964): 10.1103/PhysRev.134.A1329
- Finnis-Sinclair N-body potential for alpha-iron (Cserti et al. 1994): 10.4028/www.scientific.net/SSP.35-36.545

### Step 2: Compute Homogeneous Reference Core Widths
- Role: process
- Action: For each interatomic potential, simulate a homogeneous crystal (no interface) containing a dislocation. Record these values internally for later inclusion in the scored output files.
- Evidence: `/app/outputs/homogeneous_reference_log.txt`

### Step 3: Compute Core Widths for Johnson Pair Potential
- Role: scored (load-bearing)

For each, apply the appropriate uniform shear strain to maintain equilibrium. After conjugate-gradient relaxation, measure the core half-width (in units of a0) and identify the configuration type. Include the homogeneous reference width as a row with position 'homogeneous'. Write a CSV file with columns position_a0, core_width_a0, configuration_type.
- Output file: `/app/outputs/core_widths_pair_potential.csv`
- Format: csv

- Scoring: scored by hidden verifier

### Step 4: Compute Core Widths for N-body Potential

- Output file: `/app/outputs/core_widths_nbody_potential.csv`
- Format: csv
- Contract: Same format as core_widths_pair_potential.csv. Rows for x = -2.5, -1.5, -0.5, 0, 0.5, 1.5, 2.5 and one row with position='homogeneous'.
- Scoring: scored by hidden verifier

## How you are scored
A hidden verifier will independently read both CSV files and compare your reported core widths and configuration types to reference values derived from the published study. For each position and potential, the core width is compared against a hidden target with a prescribed tolerance; matching configuration type contributes additional credit. The total reward (0 to 1) is a weighted combination of all comparisons, with roughly equal weight per distance and configuration type bonus. The verifier checks that the CSV files are well-formed and contain the required rows and columns. Simply reporting numbers without executing the simulations is not sufficient—the verifier expects the outputs to be consistent with genuine atomistic relaxation results, but only the final numbers are scored. Your task is to implement the simulation and faithfully report the measured core widths.
