# ML Prediction of Cu Oxidation State from Simulated XAS Spectra

## Problem background
Determining the oxidation state of copper in materials is critical for catalysts, energy devices, and nanomaterials. Core-level spectroscopy (EELS and XAS) encodes oxidation state information, but traditional analysis relies on expert spectral matching to known standards, which is time-consuming, sensitive to experimental variations, and not scalable. This work addresses the problem of automated, quantitative oxidation state prediction from Cu L₂,₃-edge spectra using supervised machine learning. The task is to build a random forest regression model that takes a normalized cumulative integral of a spectrum as input and predicts the average oxidation state, and to evaluate its accuracy on a held‑out simulated test set.

## Approach
The approach uses a dataset of simulated Cu L₂,₃-edge XAS spectra curated from the Materials Project and augmented with synthetic mixed‑valence spectra generated by linear combination. The raw spectra are pre‑processed: spectra corresponding to Cu metal, Cu₂O, and CuO are excluded to avoid leakage with later experimental validation. Then, ~6000 mixed‑valence spectra are created by drawing random triplets of integer‑valence spectra and combining them at random fractional proportions, with the constraint that all variants of a triplet stay together in train or test. The input feature is the normalized cumulative integral of the spectrum. The full dataset is split into training and test sets using the split indices provided in the repository. A random forest regressor with 500 trees is trained on the training features and oxidation state labels. The model is then applied to the test set to produce per‑sample predictions (mean oxidation state and standard deviation across trees), and overall regression metrics (R² and RMSE) are computed from those predictions.

## Workflow steps

### Step 1: Exclude experimental standard spectra
- Role: process
- Action: Remove the simulated spectra corresponding to Cu metal, Cu2O, and CuO from the integer-valence dataset to prevent data leakage when later validating on experimental standards (the evaluation target uses the same filtered split).
- Evidence: `/app/outputs/filtered_spectra.pkl`

### Step 2: Generate mixed-valence augmented spectra
- Role: process
- Action: Create approximately 6000 synthetic mixed-valence spectra by linear combination of the filtered integer-valence spectra using the protocol: 300 random triplets of Cu(0), Cu(I), Cu(II) spectra, each combined at 20 random fractional proportions. Preserve mixture families: all variants of a given triplet must stay together in train or test.
- Evidence: `/app/outputs/augmented_spectra.pkl`

### Step 3: Feature extraction and train/test split
- Role: process
- Action: Compute the normalized cumulative integral of each spectrum as the input feature. Partition the full dataset (integer + mixed) into training and test sets using the provided split indices from the repository.
- Evidence: `/app/outputs/features_and_labels.npz`

### Step 4: Train random forest model
- Role: process
- Action: Train a random forest regressor with 500 trees on the training features and oxidation state labels.
- Evidence: `/app/outputs/training.log`

### Step 5: Evaluate on simulated test set
- Role: scored (load-bearing)
- Action: Apply the trained model to every spectrum in the test set to obtain per-sample predictions (mean oxidation state and standard deviation across trees).
- Output file: `/app/outputs/predictions.csv`
- Format: csv
- Contract: CSV with columns: true_oxidation_state (float), predicted_mean (float), predicted_std (float). One row per test sample in the order of the test set.
- Scoring: structural audit by hidden verifier

### Step 6: Report overall metrics
- Role: scored (load-bearing)
- Action: Compute and save the overall R² and RMSE from the test set predictions.
- Output file: `/app/outputs/metrics.json`
- Format: json
- Contract: JSON object with keys: 'R2' (float), 'RMSE' (float).
- Scoring: reference match by hidden verifier
