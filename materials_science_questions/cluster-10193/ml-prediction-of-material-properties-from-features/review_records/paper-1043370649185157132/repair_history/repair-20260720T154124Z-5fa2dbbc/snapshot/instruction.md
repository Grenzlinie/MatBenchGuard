# ML Prediction of Cu Oxidation State from Simulated XAS Spectra

## Problem background
Determining the oxidation state of copper in materials is critical for catalysts, energy devices, and nanomaterials. Core-level spectroscopy (EELS and XAS) encodes oxidation state information, but traditional analysis relies on expert spectral matching to known standards, which is time-consuming, sensitive to experimental variations, and not scalable. This work addresses the problem of automated, quantitative oxidation state prediction from Cu L₂,₃-edge spectra using supervised machine learning. The task is to build a random forest regression model that takes a normalized cumulative integral of a spectrum as input and predicts the average oxidation state, and to evaluate its accuracy on a held‑out simulated test set.

## Approach
The approach uses a dataset of simulated Cu L₂,₃-edge XAS spectra curated from the Materials Project and augmented with synthetic mixed‑valence spectra generated by linear combination. The raw spectra are pre‑processed: spectra corresponding to Cu metal, Cu₂O, and CuO are excluded to avoid leakage with later experimental validation. Then, ~6000 mixed‑valence spectra are created by drawing random triplets of integer‑valence spectra and combining them at random fractional proportions, with the constraint that all variants of a triplet stay together in train or test. **The random seed for the generation process is fixed to 42 (Python's `random.seed(42)`)** to ensure that the resulting mixed‑valence spectra match the train/test split indices provided in the resource. The input feature is the normalized cumulative integral of the spectrum, computed as described below. The full dataset is split into training and test sets using the split indices provided in the resource. A random forest regressor with 500 trees is trained on the training features and oxidation state labels. The model is then applied to the test set to produce per‑sample predictions (mean oxidation state and standard deviation across trees), and overall regression metrics (R² and RMSE) are computed from those predictions.

## Workflow steps

### Step 1: Exclude experimental standard spectra
- Role: process
- Action: Load the integer‑valence Cu L‑edge spectra from the provided dataset. Remove the simulated spectra for Cu metal, Cu₂O, and CuO to prevent data leakage when later validating on experimental standards.

### Step 2: Generate mixed-valence augmented spectra
- Role: process
- Action: Set the random seed to 42 (`random.seed(42)` in Python) to guarantee reproducibility with the provided split indices. Create approximately 6000 synthetic mixed‑valence spectra by linear combination of the filtered integer‑valence spectra using the protocol: 300 random triplets of Cu(0), Cu(I), Cu(II) spectra, each combined at 20 random fractional proportions. Preserve mixture families: all variants of a given triplet must stay together in train or test.

### Step 3: Feature extraction and train/test split
- Role: process
- Action: Compute the normalized cumulative integral of each spectrum as the input feature. **For each spectrum, first compute the cumulative sum of intensity values along the energy axis (in the order they appear in the data). Then divide all cumulative values by the total integral of the spectrum (i.e., the cumulative sum at the last energy point). This yields a normalized cumulative distribution that ranges from 0 to 1, independent of the original spectral intensity scale.** Load the train/test split indices from the provided resource and partition the full dataset (integer + mixed) accordingly.

### Step 4: Train random forest model
- Role: process
- Action: Train a random forest regressor with 500 trees on the training features and oxidation state labels.

### Step 5: Evaluate on simulated test set
- Role: scored (load-bearing)
- Action: Apply the trained model to every spectrum in the test set to obtain per‑sample predictions (mean oxidation state and standard deviation across trees).
- Output file: `/app/outputs/predictions.csv`
- Format: csv
- Contract: CSV with columns: `true_oxidation_state` (float), `predicted_mean` (float), `predicted_std` (float). One row per test sample in the order of the test set.

### Step 6: Report overall metrics
- Role: scored (load-bearing)
- Action: Compute and save the overall R² and RMSE from the test set predictions.
- Output file: `/app/outputs/metrics.json`
- Format: json
- Contract: JSON object with keys: `R2` (float), `RMSE` (float).
