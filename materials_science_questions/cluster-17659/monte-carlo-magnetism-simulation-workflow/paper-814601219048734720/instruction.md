# Edwards Measure Construction for the Kob-Andersen Model via Auxiliary Hamiltonian Simulations

## Problem background
Granular materials and structural glasses undergo slow compaction and aging, falling out of equilibrium. Edwards proposed a statistical mechanics description based on the number of blocked (jammed) configurations—the Edwards entropy and associated temperature. A key question is whether this flat measure over blocked configurations corresponds to the actual dynamical measure generated by realistic, non-mean-field models. The Kob-Andersen lattice glass model in three dimensions is a paradigmatic model with kinetic constraints that reproduce glassy dynamics. This task investigates the relationship between the Edwards measure and the long-time dynamic measure in this model.

## Approach
Two independent simulation protocols are used. In the Edwards protocol, an auxiliary Hamiltonian is defined that counts mobile particles (particles with fewer than four occupied neighbors before and after a hop). By annealing this auxiliary model at fixed particle number, one samples configurations with low mobility and can compute the Edwards entropy per particle s_edw(ρ) via thermodynamic integration. At a chosen density, zero‑temperature blocked configurations yield the Edwards structure function g_edw(r). In the dynamic protocol, a compaction simulation is performed with open boundaries and a chemical potential that is slowly raised, mimicking a piston. The long‑time configurations provide the dynamic structure function g_dyn(r) and, via mobility and mean‑square displacement measurements and the Einstein relation, a dynamical temperature T_dyn. The Edwards temperature T_edw is obtained by differentiating the Edwards entropy and using the equilibrium entropy relation s_equil(ρ) = -ρ ln ρ - (1-ρ) ln(1-ρ). The two independent sets of observables (Edwards vs. dynamic) are compared.

## Workflow steps

### Step 1: Run auxiliary model simulations for Edwards measure
- Role: process
- Action: Implement the Kob-Andersen model on a 3D cubic lattice. For several fixed particle numbers covering densities from 0.5 to 0.88, introduce the auxiliary Hamiltonian counting mobile particles (a particle is mobile if it could move under the kinetic rule). Perform Monte Carlo simulated annealing at constant particle number to record the average auxiliary energy versus auxiliary temperature. At density ~0.87, save zero‑temperature blocked configurations.
- Evidence: `/app/outputs/auxiliary_simulation.log`

### Step 2: Compute Edwards entropy per particle as a function of density
- Role: scored (load-bearing)
- Action: From the recorded average auxiliary energy curves, perform thermodynamic integration to obtain Edwards entropy S_edw(N) for each particle number. Convert to entropy per particle s_edw(ρ). Write the resulting density–entropy pairs to the output file.
- Output file: `/app/outputs/edwards_entropy.csv`
- Format: csv
- Contract: CSV with header: density, s_edw. Each row gives a density (float, e.g. 0.500, 0.550, …) and the corresponding Edwards entropy per particle (float).
- Scoring: scored by hidden verifier

### Step 3: Compute Edwards temperature at density 0.848
- Role: scored
- Action: Using the equilibrium entropy s_equil(ρ) = -ρ ln ρ - (1-ρ) ln(1-ρ) and its derivative d s_equil/dρ = -μ, compute μ at ρ = 0.848. From the Edwards entropy data in edwards_entropy.csv, numerically differentiate s_edw(ρ) and compute T_edw^{-1} = -(1/μ) d s_edw/dρ at ρ = 0.848. Write the result.
- Output file: `/app/outputs/edwards_temperature.json`
- Format: json
- Contract: JSON object with key "T_edw" (float).
- Scoring: scored by hidden verifier

### Step 4: Compute Edwards structure function at density ~0.87
- Role: scored (load-bearing)
- Action: From the saved zero‑auxiliary‑temperature configurations at density ≈0.87, compute the pair correlation function g_edw(r) = probability that two sites at distance r are both occupied. Write the distances and correlation values.
- Output file: `/app/outputs/edwards_structure.csv`
- Format: csv
- Contract: CSV with header: r, g_edw. r is integer lattice distance; g_edw is the correlation function value (float).
- Scoring: scored by hidden verifier

### Step 5: Run dynamic compaction simulation of the Kob-Andersen model
- Role: process
- Action: Implement the KA model with open boundaries and a topmost layer where particles are created/destroyed with a chemical potential μ. Start at low density, ramp μ from 1 to 3 over many sweeps. Record density evolution, and at late times save particle configurations and compute mobility χ(t,t_w) and mean-square displacement B(t,t_w) for several waiting times.
- Evidence: `/app/outputs/compaction_simulation.log`

### Step 6: Compute dynamic structure function at density ~0.87
- Role: scored (load-bearing)
- Action: From the late‑time configurations saved during compaction, compute the dynamic pair correlation function g_dyn(r) and write the distances and values.
- Output file: `/app/outputs/dynamic_structure.csv`
- Format: csv
- Contract: CSV with header: r, g_dyn. r is integer lattice distance; g_dyn is the correlation function value (float).
- Scoring: scored by hidden verifier

### Step 7: Compute dynamic temperature at density 0.848
- Role: scored (load-bearing)
- Action: Using the mobility χ(t,t_w) and mean-square displacement B(t,t_w) data from compaction, perform a linear fit (Einstein relation) to extract the dynamical temperature T_dyn as the slope at a waiting time corresponding to density 0.848. Write the value.
- Output file: `/app/outputs/dynamic_temperature.json`
- Format: json
- Contract: JSON object with key "T_dyn" (float).
- Scoring: scored by hidden verifier

## How you are scored
A hidden verifier independently scores each of the five output artifacts against a reference derived from the original study. The entropy curve is assessed by comparing the whole density–entropy relationship; the two temperature values and the two structure functions are evaluated at the specified densities. Each artifact carries a weight (entropy 40 %, temperatures 30 %, structure functions 30 %), and the final reward is the weighted sum of these scores. The verifier uses tolerance-based comparisons; statistical noise and implementation differences are accounted for. Simply reporting the expected numbers without a valid workflow will not suffice, as the verifier checks the consistency of the entire pipeline's outputs.
